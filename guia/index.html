O que um cineasta vê no seu vídeo

Manda um link ou um arquivo e recebe a leitura técnica: movimento de câmera bloco a bloco, esquema de luz, paleta em hex, ritmo de montagem, trilha e som, grafismo, e um passo a passo de como refazer aquilo. Sem transcrever uma palavra da fala.

Começar o guia Ver no GitHub
O que é

Leitura de linguagem audiovisual, não transcrição

Transcrição já existe (inemaVOX/Whisper). O que faltava era alguém olhar o vídeo e dizer como ele foi feito.

🎥 Câmera bloco a bloco

Cada trecho com timecode: plano, ângulo, movimento (dolly, gimbal, whip-pan, drone, orbital), velocidade e o que aquilo faz na cena.

🎨 Luz, cor e montagem

Paleta em hex, esquema de luz, look e lente aparente; cortes por minuto, ritmo, transições, corte no beat e uso de slow-mo.

🗂️ Banco pesquisável

Toda análise vira JSON + relatório e entra num índice local. Depois é search drone, search synthwave, stats.

Como funciona

Do link ao relatório em uma chamada

Tudo local, menos a leitura visual, que é do Gemini.

link ou arquivo→ yt-dlp (≤480p)→ ffprobe: duração e formato→ Gemini: leitura de cineasta→ analise.json + analise.md→ index.jsonl (banco)

Por que 480p

Cor, luz e movimento se leem bem nessa resolução e o upload fica rápido. Acima de 18 MB o arquivo é reencodado para 360p/12fps só para a análise.

O que não faz

Não roda Whisper, não devolve legenda, não clona música. Fala é com o inemaVOX; clonar faixa é com a skill musica.

Só por comando

No bot, roda apenas em /analisevideo. Link solto no Telegram continua indo para a transcrição, de propósito.

Pré-requisitos

O que precisa estar na máquina

Nada de servidor: é shell + python3 + uma chave do Gemini.

Binários

Download, leitura de metadados e consulta ao banco.

# Ubuntu/Debian
sudo apt install ffmpeg jq python3
pip install -U yt-dlp

Chave do Gemini

Lida em runtime do .env do OpenPCBot (ou do wifi). Nunca é copiada para cá.

# ~/projetos/openpcbotv2/.env
GOOGLE_API_KEY=...

Clone

O repo é a skill: o OpenPCBot aponta para cá por symlink.

git clone git@github.com:inematds/analisevideo.git \
  ~/projetos/analisevideo
Guia de uso · passo a passo

Analisar, ler e consultar

Comandos reais. S=~/projetos/analisevideo/analisevideo.sh

1

Analisar um link

Baixa, lê o visual e arquiva. O caminho do relatório sai na última linha.

bash $S analisa "https://www.youtube.com/shorts/XXXX"  # baixa, analisa, indexa
2

Analisar um arquivo local

Serve para material que o yt-dlp não pega (site logado) ou para um trecho já cortado.

bash $S analisa ~/videos/reel.mp4 reel-marca --keep-src  # guarda o fonte.mp4
3

Focar a análise numa pergunta

--prompt acrescenta um pedido específico, respondido no campo pedido_extra.

bash $S analisa "<url>" --prompt "como eles seguram a atenção nos 3 primeiros segundos"
4

Ler o relatório de novo

Markdown pronto para colar em briefing, roteiro ou ordem de serviço.

bash $S ver reel-marca      # relatório
bash $S json reel-marca     # estruturado, para script
5

Consultar o banco

É aqui que a coisa vira acervo: procurar por movimento, look, gênero da trilha ou tag.

bash $S list 10               # últimas 10 análises
bash $S search "drone"       # tudo que tem drone
bash $S stats                # movimentos e tags mais frequentes
6

No Telegram, pelo OpenPCBot

A skill é ligada como comando do bot — não dispara sozinha por link.

/analisevideo <url|caminho>   # resumo + analise.md anexado
/analisevideo search drone
/analisevideo stats
